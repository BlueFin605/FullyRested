# FullyRested review — 2026-09-29

A snapshot of the state of FullyRested on 2026-09-29, what was wrong with it, and why the refresh plan is shaped the way it is. This is not a living doc: the plan and its progress live on the BlueFinWiki kanban board (initiative **AI Refresh**, `e58ec7d8-09c2-4d67-81b7-9b1b2e72d989`).

## What it is

A desktop Postman alternative: **Electron 27 + Angular 14**, about 7.8k lines. The README's pitch is that requests live as plain JSON files that can be kept in git, and that requests can be chained.

- 198 commits from 2023-10-12 to 2024-01-23; the last is `34a7c6b`, "renamed as FullyRested".
- Added to Home as a submodule in `1219e4c`.

Features that exist:
- **Files:** one JSON file per request (`.reasyreq`) and one per collection (`.reasycol`).
- **Environments:** `{{variable}}` placeholders, and `{{$secret}}` placeholders whose values are kept in the OS keychain via `keytar`.
- **Auth:** none, inherit, basic, bearer and AWS SigV4.
- **Runs:** named variants of a request that override its variables, headers, params, auth and validation.
- **Validation:** status code, headers, and a JSON Schema check on the body.
- **Response viewers:** JSON, XML, HTML and image.

### Layout

| Path | What |
|---|---|
| `App/FullyRested/main.js` | Electron main process: sends HTTP requests (axios), applies auth, handles files and the keychain |
| `App/FullyRested/preload.js` | IPC bridge with allow-listed channels |
| `App/FullyRested/src/` | Angular renderer (UI, variable substitution, validation) |
| `App/shared/{runner,builder,validator}` | Start of a shared library for the app and CLI (see Findings) |
| `App/cli-command` | CLI stub |
| `Test Collection/` | Example collection and requests |

### How a request runs (before the refresh)

1. `edit-request-run.component.ts` `test()` builds an `ExecuteRestAction`, merging the run and action headers, params, auth and validation.
2. `ExecuteRestCallsService.executeTest` adds the selected environment's and the collection's auth, variables and secrets, then calls `replaceVariables()`.
3. The action goes over the `testRest` IPC channel to `main.js` `executeAction`, which applies auth and sends the request with axios.
4. The renderer's `ValidateResponseService` validates the result.

## Findings

### Architecture

- **The split into `shared/` stopped halfway.** The folder names don't match what's inside:
  - `runner` holds the data model, not a runner.
  - `builder` holds the builder plus variable substitution.
  - `validator` holds one 5-line interface.
- **The CLI can't reuse what it needs.** Request execution and auth live in `main.js`, and validation lives in the Angular `ValidateResponseService`.
- **Imports are inconsistent.** Some go to a package's built output (`../../shared/runner`), others to its source (`shared/builder/src`), some through seven levels of `../`. There is no npm workspace: four separate `package.json`s and lockfiles.

### Bugs

| Bug | Where | Evidence |
|---|---|---|
| A variable value containing `"` throws `SyntaxError` | `shared/builder` `replaceVariables()` (JSON.stringify → regex → JSON.parse) | Reproduced |
| A secret containing `$&` is mangled (`ab$&cd` → `ab{{$tok}}cd`) | `VariableSubstitution.substituteValue` (`String.replace` special patterns) | Reproduced |
| `replaceVariables()` returns a plain object typed as `ExecuteRestAction`, so its methods are gone | same | Reproduced |
| Non-2xx responses lose their body (axios throws; the catch block returns only status and headers) | `main.js` `executeAction` catch | Read |
| AWS SigV4 signs a hard-coded `GET` with no body, so only body-less GETs work | `main.js` `addAwsSigToRequest` | Read |
| `content-type: none` is sent on requests with no body | `main.js` `executeAction` | Read |
| `CONNREFUSED` / `HOSTUNREACH` / `AI_AGAIN` / `CONNABORTED` never match Node's `E…` codes, so every failure shows as -99 | `main.js` `executeAction` | Read |
| `RestTypeVerb.option` is sent as method `OPTION` | `main.js` `executeAction` | Read |
| `addPasswords` `return`s at the first `null` field, so later secrets never load | `main.js` | Read; a test pins it |
| `keytar.setPassword` is not awaited | `main.js` `stripPasswords` | Read |

### Secrets

- **Run secrets saved in plain text.** Secrets on a request's runs are written to `.reasyreq` files unencrypted. Only collections are sanitised before saving. No committed file contains any yet.
- **Auth credentials saved in plain text.** AWS keys, basic-auth passwords and bearer tokens are stored as-is unless a `{{$secret}}` reference is typed into the field. The test collection only holds dummy values (`akey` / `skey`).
- **Secrets logged.** `main.js` logs keychain values, whole requests and collections; the renderer logs actions, auth and runs.
- **Local state file.** `current_state.json` in the app's userData folder holds the open tabs, secret values included, in plain text.

## Spike and dry-run results

These settled the design of the Core engine epic.

- **Layout: `file:` links, not npm workspaces.** Workspaces would hoist dependencies, which breaks `angular.json`'s `./node_modules/@angular/material/...` style path. Instead:
  - Angular imports `core`'s **source** through a tsconfig `paths` mapping. `ng build` passed.
  - Node consumers (`main.js`, the CLI) use `"@fullyrested/core": "file:../core"` and load its built `dist/`. `require` resolved.
- **SigV4:** `@smithy/signature-v4` 5.7.4 with `applyChecksum: false` reproduces the AWS test-suite signatures:
  - get-vanilla: `5fa00fa31553b73ebf1942676e86291e8372ff2a2260956d9b8aae1d763fbf31`
  - post-vanilla: `5da7c1a2acd57cee7505fc6676e4e544621c30862966e37dddb68e92efbe5d6b`
- **JSON Schema: switch to Ajv.** `@hyperjump/json-schema` 1.6.7 is ESM-only (`"type": "module"`), and Electron 27's Node 18 cannot `require()` ESM. Ajv 8 (`ajv/dist/2020` + `ajv-formats`) is CommonJS and works everywhere. Ajv's catches:
  - A draft-07 `$schema` URI fails to compile. `core` strips `$schema` and treats every schema as 2020-12.
  - Errors read like `/id must be integer`.
- **Angular's TypeScript 4.7 is stricter than `core`'s TypeScript 5.4.** It rejects `result as T` with TS2352; `core` casts via `as unknown as T`.
- **Bundle size:** adding Ajv to `core` takes the Angular bundle to 2.15 MB. That's over the 2 MB warning and under the 3 MB error limit.
- **Electron smoke test.** Running `core`'s `executeRequest` inside Electron 27's Node (`ELECTRON_RUN_AS_NODE=1`) against `jsonplaceholder.typicode.com/todos/0` printed `18.17.1 404 {}`.
- **Full dry run.** Every Ready task in the Core engine and Secrets hygiene epics was executed in a scratch copy: 41 core tests pass, and `ng build`, the CLI build and `node --check main.js` all pass.
- **Log removal is safe to do by line.** All 187 renderer `console.log` calls fit on one line, and none is the only body of a brace-less `if` / `else` / loop.

## Decisions baked into the plan

- **One `@fullyrested/core` package** (`App/core`) replaces `App/shared`. It holds the model, substitution, auth, execution, validation and keychain walking.
- **`core/src` stays isomorphic:** no `node:` or `fs` imports, because Angular bundles it into the renderer.
- **`core` compiles to CommonJS with no ESM-only dependencies,** so Electron 27's Node can load it.
- **Substitution is single-pass and done per string** (`substituteText` / `substituteDeep`) rather than through JSON text. Unknown and inactive names become `''`, as before.
- **`executeRequest` never throws:**
  - Network failures come back as negative statuses (-1 … -8, and -99 for anything else).
  - Non-2xx responses keep their body.
  - The user's own `content-type` header wins over the one from the body type.
- **Validation compares header names case-insensitively,** and an empty body counts as "no payload".
- **Keychain names:** collections keep `fullyrested-collection-<guid>`; request files get `fullyrested-request-<id>`.
- **Old files keep their secrets.** `loadSecrets` keeps a plain-text `$value` that is already in a file when the keychain has none; the next save moves it into the keychain.
